# Analyzer v1: Python vertical slice

Status: **milestone 2**. Code: `src/xraymyrepo/analyzer/`. Contract: `docs/cim/CIM-v1.md` (unchanged).

The analyzer turns a working tree into a CIM v1 `SnapshotDocument`. It is a library first
(`xraymyrepo.analyzer.analyze`) with a minimal CLI (`xray analyze PATH`). It has no dependency on
PostgreSQL, web frameworks or the frontend, and it never writes to a database.

```python
from xraymyrepo.analyzer import analyze
from xraymyrepo.cim import RepositoryRef

doc = analyze("path/to/repo", repository=RepositoryRef(host="github.com", owner="o", name="r"),
              commit_sha="<40 hex>")
doc.to_canonical_json()
```

```bash
xray analyze path/to/repo [--commit SHA] [--repository HOST/OWNER/NAME] [-o cim.json]
```

## Pipeline

| Stage | Module | Output |
|---|---|---|
| 1. inventory | `inventory.py`, `origin.py` | directories, files, language, git blob id, origin |
| 2. manifests | `manifests.py` | Python project roots, `pyproject.toml` package and dependencies |
| 3. parsing | `python/parse.py`, `python/symbols.py`, `python/imports.py` | declarations, import references, issues |
| 4. resolution | `python/resolve.py` | resolved imports, unresolved references |
| 5. construction | `build.py` | CIM records |
| 6. validation | `SnapshotDocument` (the contract) | a valid document or `AnalyzerContractError` |

Stages exchange plain frozen dataclasses (`facts.py`). The analyzer reuses the contract's key
functions and models and duplicates none of its validation. A contract violation in the output is an
analyzer bug and is raised, never repaired. Invalid inputs (for example a malformed commit SHA) raise
`pydantic.ValidationError` before any work starts.

The snapshot declares `coverage = [python: IMPORTS]` and `languages = [python, toml]`. Producers:
`structure-extractor` (tree, origins), `python-extractor` (declarations, imports), `manifest-extractor`
(`pyproject.toml`). All three have version `ANALYZER_VERSION` (`0.1.0`) and the hash of an empty config.

## 1. Inventory

* Entries are walked sorted by name. Symbolic links and Windows junctions are never followed
  (`symlink_skipped`, info issue). Paths that cannot be keys are skipped (`invalid_path`).
* **Ignored** paths are not recorded at all and are part of `AnalysisConfig.ignore_globs`. Default:
  `**/{.git,.hg,.svn,.venv,venv,node_modules,__pycache__,.mypy_cache,.pytest_cache,.ruff_cache,.tox,.nox}/**`.
* Directories with no recorded file are not recorded (git cannot represent them).
* `blob_sha` is the git blob id (SHA-1) of the bytes on disk. It equals git's id when the checkout
  applies no line-ending or clean-filter conversion.
* **Language** by extension: `.py .pyi` python, `.toml` toml, `.json` json, `.md .markdown` markdown,
  `.rst` restructuredtext, `.adoc` asciidoc, `.sh .bash` shell, `.ts .tsx .mts .cts` typescript,
  `.js .jsx .mjs .cjs` javascript, `.yaml .yml` yaml, `.html` html, `.css` css; otherwise none.

### Origin rules (first match wins)

| Rule | Origin | Matches | Evidence |
|---|---|---|---|
| `origin.vendor_directory` | vendored | a path directory named `vendor`, `vendored`, `third_party` | convention `vendor/**` |
| `origin.build_directory` | build_artifact | a path directory named `build`, `dist` or `*.egg-info` that has no `__init__.py` | convention `dist/**` |
| `origin.generated_header` | generated | a comment in the first 10 lines containing `@generated`, `auto-generated`, `autogenerated`, `do not edit` or `generated by` (case-insensitive; `#` comments for python/shell/toml/yaml, `//` `/*` for ts/js) | span of the comment line, `ast_type: comment` |
| `origin.docs_extension` | docs | `.md .markdown .rst .adoc` | convention `*.md` |
| `origin.default_source` | source | anything else | convention |

Marker directories themselves get the same origin (convention `vendor/`). Other directories have no
origin classification. With the default exclusion policy, vendored, docs and build-artifact files are
`excluded` (file node only). Generated files are extracted.

**Extraction status:** `excluded` by policy; Python files `full`, `partial` or `failed`; `pyproject.toml`
`full` (or `failed` when it is not valid TOML); every other file `unsupported`.

## 2. Python projects and manifests

* A directory with `pyproject.toml`, `setup.cfg` or `setup.py` is a project root. Its import roots are
  `<root>/src` (if it exists) then `<root>`. Files outside every project use the repository root.
* `module_name` is the file's dotted path below the first import root that contains it (`__init__.py`
  names the package). It is omitted when a path segment is not an identifier.
* Only PEP 621 metadata in `pyproject.toml` is read: `[project].name` becomes `pkg:pypi:<name>` (with
  the `manifest` role), and `[project].dependencies` and `[project.optional-dependencies]` become
  `ext:pypi:<name>` nodes with config evidence (`py.manifest.dependency`,
  `py.manifest.optional_dependency`). Names are PEP 503-normalized. A package name declared twice keeps
  the first manifest (`duplicate_package` warning).
* `REQUIRES` edges are **not** extracted in this milestone (no `toml` coverage is declared).

## 3. Python declarations

Parsed with the standard library `ast`.

| Construct | Node |
|---|---|
| `class` | `type`, `type_kind: class` |
| `type X = ...` (3.12) | `type`, `type_kind: type_alias` |
| `def` at module level or inside a function | `function`, `function_kind: function` |
| `def` in a class | `method`; `__init__` → `constructor`; `@property` / `@cached_property` → `accessor` |
| `async def` | as above, `is_async: true` |

* Parent = nearest enclosing class or function, else the file; compound statements are not scopes.
  Keys follow the contract (`file.py#Outer.inner`). Repeated names in one scope get `@2`, `@3`, ...
* `@overload` stubs are one node with their implementation; `@x.setter` / `.getter` / `.deleter` are
  one node with the property `x`.
* Not nodes: variables, fields, decorators, lambdas, comprehensions.
* Spans include decorators. Columns are converted from `ast`'s UTF-8 byte offsets to code points.
* Declarations are observed: they carry `span` and provenance (`py.declaration.class`,
  `py.declaration.function`, `py.declaration.type_alias`) and no evidence list, as in the golden fixture.
* Fingerprints (`content_hash`, `signature_hash`) are not produced yet (they need the normalized token
  stream, which is not implemented), so they are left empty as the contract allows.

### Failures (one bad file never stops the analysis)

| Problem | Status | Issue (`code`, rule) |
|---|---|---|
| undecodable source (PEP 263 encoding, BOM aware) | failed | `decode_error`, `py.decode` |
| syntax error, null bytes, too deeply nested | failed | `parse_error`, `py.parse` (span from `SyntaxError`) |
| crash while extracting declarations | failed | `extractor_error`, `py.declaration` |
| crash while extracting imports | partial (declarations kept) | `extractor_error`, `py.import` |

## 4. Imports and resolution

Extracted: `import a.b [as c]`, `from [.]a import b [as c]`, `from a import *`, and dynamic calls
`importlib.import_module(...)`, `import_module(...)` (imported from `importlib`) and `__import__(...)`.
The source is the innermost named scope (file, class or function). Imports in the body of
`if TYPE_CHECKING:` are `is_type_only`.

Module lookup, in order:

1. **relative** (`py.import.relative`): from the file's directory, one level up per extra dot; never
   above the repository root.
2. **local** (`py.import.absolute`): the nearest project's import roots, else the repository root;
   first root wins. A regular package (`x/__init__.py`) wins over `x.py`, then `x.pyi`, then a
   namespace directory. Local modules shadow the standard library.
3. **standard library** (`py.import.stdlib`): top-level name in the frozen `STDLIB_MODULES` list (union
   of CPython 3.10 and 3.13) → `ext:python-stdlib:<name>` (basis `resolved`, evidence = import spans).
4. **declared dependency** (`py.import.external`): normalized top-level name declared by the nearest
   project's `pyproject.toml` → `ext:pypi:<name>`.
5. otherwise **unresolved**, `not_found`, with the specifier as written.

Targets, for `from m import n` (most specific node first):

1. `n` is the only top-level declaration named `n` in `m` → that symbol;
2. several declarations of `n` compete (`f`, `f@2`) → the module file;
3. `n` is bound in `m` by an import → resolved **through** `m` (`via: [m]`, recursively, cycle-safe);
4. `m` is a package and `m.n` a submodule → that file;
5. otherwise (a variable, `*`, or a file that failed to parse) → the module file.

`import a.b` targets `a/b.py` (or `a/b/__init__.py`). An import that reaches only a namespace directory
cannot target a node and is unresolved (`py.import.namespace_package`). An import of a module's own name
from itself is dropped (`IMPORTS` cannot self-loop). Dynamic imports resolve only with a literal absolute
module name (`is_dynamic: true`, rule `py.import.dynamic_call`). Otherwise they are unresolved,
`dynamic`, with the call text as `raw_text`.

All occurrences of one (source, target) pair form one edge: `occurrence_count` = distinct statements,
evidence = their spans (≤ 20, in source order), `specifiers` and `imported_names` = sorted unions,
`is_type_only` / `is_dynamic` = all occurrences, `via` = the first occurrence's.

## Golden fixture

`tests/analyzer/test_golden_analyzer.py` runs the analyzer on `fixtures/golden/v1/repo` and compares the
slice it is responsible for with `expected_cim.json`, exactly and in both directions. The slice covers:

* the structure nodes, Python symbols, and `pypi` / `python-stdlib` packages;
* Python `IMPORTS` edges;
* origins and the `pyproject.toml` manifest role;
* Python unresolved references and issues.

Two documented differences:

* TypeScript and JSON files are `unsupported` here (`full` in the fixture), because those extractors do
  not exist yet.
* Issue messages are not compared. They are the parser's text (CPython 3.13 reports `invalid syntax`;
  the fixture spells `invalid syntax: expected a parameter name`).

## Review decisions (2026-10-07)

1. **Syntax-error messages are not compared** with the golden fixture, intentionally: the text is
   CPython-version specific. Code, severity, file, span and provenance are compared exactly.
2. **Declaration nodes carry `span` + provenance and no evidence list**, as the locked CIM contract
   allows for observed nodes. No separate evidence-list requirement applies.
3. **Namespace-package imports** that cannot target a node remain unresolved references
   (`py.import.namespace_package`): accepted v1 limitation.
4. **Merged edges keep the first occurrence's `via`** when occurrences reach the target through
   different re-export files: accepted v1 limitation.

## Known limitations (v1)

* Module names must equal distribution names to resolve externals (`import yaml` with `PyYAML` stays
  unresolved). No `top_level.txt` / installed-metadata lookup.
* Only PEP 621 `pyproject.toml` metadata; Poetry, `setup.py`, `setup.cfg` and requirements files mark
  project roots but are not read for dependencies.
* Absolute imports search only the importing file's own project roots; cross-project imports in a
  monorepo resolve only via declared dependencies.
* `type_kind` is always `class` for classes (protocols and enums need base-class resolution).
* `is_reexport` is never set for Python (Python has no re-export syntax); re-exports are still resolved
  through.
* `.gitignore` is not read; only `ignore_globs` apply. Blob ids come from the working tree, so analyze a
  clean checkout of the recorded commit.
* Not implemented: TypeScript, Tree-sitter, `CALLS`, `INHERITS`, `HANDLES`, `TESTS`, `REQUIRES`, roles
  other than `manifest`, fingerprints, persistence.
